Two-app job board — Post & Search
Greyscale + one accent · 8px scale · v1
Design decisions
  • Create Job is one page, not a wizard. Hiring managers post repeatedly and already know the shape of a posting; a single scannable page lets them tab straight through, paste from a doc, and see every required field at once. Wizards suit unfamiliar, branching flows — this is neither.
  • Salary errors anchor to the field pair. Min ≥ Max is a relationship, not a property of either input. The message sits under both fields with both outlined, so the manager isn't told "Min is invalid" when Max is the one they meant to change.
  • Validation fires on blur, re-validates on input once errored. No shouting at a field the user hasn't finished typing into; instant relief once they fix it.
  • Eventual consistency is framed as propagation, not delay. The confirmation screen says the posting is saved (with its server ID) and the board copy "may take a few moments" — a neutral note, not a warning colour, because nothing is wrong.
  • Confirmation echoes the API record verbatim. ID, slug, created timestamp and status come back from the server, so the manager can quote a reference in email and we prove what was actually stored.
  • Server errors get a summary banner AND inline errors. The banner is the focus target after a failed submit; each line links to its input. Screen-reader users hear the count first, sighted users see the map.
  • App 2 is filter-rail-first, App 1 is toolbar-first. Candidates narrow a large unknown set; managers scan a small known one. Same type, spacing and components — different information density on purpose.
  • Filters show as removable chips above the results. The rail can scroll out of view; the chips keep the active query visible and one click from undoable, and they're the aria-live region for result counts.
  • Skeletons, not spinners, in App 2. The results layout is predictable, so a skeleton preserves scroll position and perceived speed. App 1's submit uses a spinner because one action is blocking.
  • Remote disables rather than hides Location. Managers still often want a region for timezone; the field relabels to "Region (optional)" instead of vanishing, avoiding a layout jump.

Make failure legible: the manager should always know how many things are wrong, which, and how to get to them.

App 1 paginates (stable, auditable); App 2 loads more (scannable, SEO pages still exist behind ?page=).
Purpose

Freeze the primitives both apps share so the build step has one source of truth for states.

Data

None — presentational only. Copy shown is illustrative.

Interactions

Every control has a visible focus ring (3px accent, 2px offset) that is never removed on mouse use. Hover states are advisory only; nothing is hover-only.

States

Default, hover, focus, disabled, error, loading — drawn for each primitive above. Disabled controls stay in the tab order via aria-disabled where the reason must be announced.

A11y

Minimum contrast 4.5:1 for text, 3:1 for borders and icons. Touch targets ≥44px in App 2 mobile. Error text is programmatically linked, not adjacent-only. Toasts are polite live regions; error toasts are role="alert".
